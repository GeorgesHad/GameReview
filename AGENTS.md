# Engineering instructions

- Read `football_review_implementation_requirements.md` in full before changing product behavior. Keep the approved specification intact. Keep phase status and open decisions in `PROGRESS.md` and explain architecture changes in `ARCHITECTURE.md`.
- Work one phase at a time. Validate the real DEV upload and playback path before building out related screens. Keep manual local execution optional. Maintain a private repository and free-plan deployment path.
- Keep the same-origin React/Hono application and versioned REST/JSON API. Keep shared contracts framework independent. Add services, repositories and provider adapters as product features need them. Keep provider SDK details at those boundaries.
- Authorize every protected action server-side using verified identity and current active membership. Apply team, role, publication and note-visibility checks. Test both allowed and denied outcomes. Use SQL constraints, explicit transactions, RLS and restrictive grants. Treat privileged database access as a bypass that requires server authorization.
- Keep original videos in private R2. Transfer them directly between browser and R2, using scoped expiring URLs. Preserve stable recording IDs and note references across uploads and restores. Use streaming or incremental processing for large files. Keep private API, Auth and media data out of persistent browser caches and logs.
- Use version-controlled forward migrations. Keep DEV data, storage and credentials separate from PROD. Keep secrets in platform settings and out of source, test fixtures, chat, frontend bundles and workflow output. Obtain approval before destructive data operations or production deployment.
- Install with `npm ci` using the version in `.nvmrc`. Run `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, `npm run check:deploy` and `npm run test:e2e` before opening a PR. Update OpenAPI when the REST contract changes. List which checks actually ran, including any pending cloud or device checks.
